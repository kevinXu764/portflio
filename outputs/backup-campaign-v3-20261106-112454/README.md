## 浏览方式

- 第一屏自动展示实体卡片队列，可用顶部按钮暂停；向下滚动、触屏上滑或点击顶部“作品”进入第二屏。
- 第二屏左右拖动卡片、使用左右箭头/键盘方向键或圆点切换。三张真实作品可以点击卡片或“查看详情”进入详情。
- 后三张分类卡先展示封面，项目内容待补充，不提供详情跳转。
- 每张卡片独立保存摆动状态，左右倾转上限 28°、侧倾上限 12°，松手立即回弹。
- 详情页保留章节导航、流程状态切换、图片放大及录屏；页尾只在三个真实作品间切换。
- 页面底部不再显示项目专属标签；通过通用作品轮播和“查看详情”进入案例。
- 系统“减少动态效果”模式停用队列自动播放与倾转，保留全部切换与导航能力。

## 桌面与移动布局

桌面宽屏采用全宽展示：第一屏左侧主标题、右侧队列；第二屏左侧卡片、右侧案例介绍与操作。页面最大宽度 1600px，相机视野随真实舞台比例调整。手机使用上方卡片、下方介绍；矮横屏采用左右布局。详情使用最大 1440px 阅读画布并随宽度重排图文。

## 维护入口

- `works.js`：六张卡片的名称、说明、标签、封面和占位状态。
- `assets/covers.js`：为了支持直接双击打开而内嵌的六张封面。封面原文件也在同目录。修改后运行 `node build-covers.cjs` 更新内嵌资源。
- `app.js`：3D 模型、相机、滚动切屏、拖拽与回弹参数。
- `styles.css`：首页各端布局。
- `detail.js`、`detail.css`：三个案例的外层导航与页面布局。
- `cases/`、`media.js`：案例正文、媒体和原站演示交互。
- `build-detail.cjs`：修改详情模块后，用已有 esbuild 包构建 `assets/detail.bundle.js`。浏览网站本身不需要 esbuild。

添加真实作品时，将对应预留项的 `placeholder` 改为 `false`，补齐封面、摘要与详情路由，同时更新详情页的案例注册。不要只改卡面文字就保留空详情。

## 存储与接口

无业务后端、无真实提交或上传。浏览器存储仅保存当前卡片、浏览屏幕、播放偏好和调试视角。三个案例展示原设计中的固定界面与示例流程，不会创建真实订单、聊天或候选记录。

来源：Windows 的 `branch0` 与 `testcode/card1`。两份源网站保持原状，本站独立交付至 `branch2`。

## v2 字体与页面文字调整

主视觉标题改为两行粗体英文 Design / Showcase。移除网站署名及重复的作品统计、分类标签与操作提示；保留案例正文和截图中的示例信息。手机首页项目标题为 32–36px，正文为 14–15px，主要入口为 15–16px，配合提高字重和文字对比。详情页正文排版不变。

## v3 第二屏与封面清晰度

第二屏卡片额外放大 12%，桌面卡片及简介整体上移；手机卡片约上移 80–100px，简介靠近卡片下方，平板根据卡片实际占宽保留间距。首屏视角和独立摆动参数不变。

三张封面以原生 1567px 宽度上传，不再缩到 1280px。当前画布在普通屏采用 1.25 倍采样，高密度屏最高 2 倍，单画布限制为 240 万像素；玻璃折射背景单独按半宽、半高绘制。纹理启用设备支持的各向异性过滤与 mipmap，减少倾转时细节丢失。

卡面作为独立的不透明表面贴纸，位于基底正面及边框最高点之前；基底中央承托面同步抬高，没有透明层覆盖图片。图片保留原图颜色与对比，玻璃边框继续承担反光和透光。未对原图做 AI 放大或重绘，图片自身的细小文字仍受原始素材清晰度限制。

## v4 第二屏卡片间距

拉开主卡与两侧卡片的距离，手机每侧约增加 20px，桌面约增加 40–50px。主卡大小、首屏队列和摆动幅度保持不变。

## v5 长阴影、文字对齐与切屏

第二屏采用已确认的左下渐消长阴影，远端逐渐变淡、变柔，两侧卡片的阴影弱于主卡。首屏卡片上的标题与说明均对齐卡片右缘。案例入口改为深色胶囊按钮“查看详情”。

地面保留在渲染场景中，其颜色和投影随切屏进度连续融入背景；接触阴影同步淡出，长阴影渐入，返回首屏按相同曲线恢复。长阴影提前完成材质编译，采用 32 次轮廓采样，排除远侧无关卡片。相机变化期间修正投影位置，避免阴影从卡片边缘错位。当前版本继续沿用原配色，未采用冷白配色预览。

## v6 内部空腔

采用已确认的内部封闭空腔版本。沿用 v5 外轮廓、尺寸、凹槽、封面位置和材质参数，仅增加独立内壁表面。封面仍是不透明的表面贴纸，内腔主要通过半透明边缘与斜视角表现。

空腔深度 0.094，平直侧壁约 0.113，后壳厚度 0.055，原凹槽处前壳至少 0.056（均为模型单位）。内壁材质随六张卡片一同切换。实时透射采用内壁材质近似，不是离线多次折射光线追踪。

保留此前的左右摆动、卡片间距、深色“查看详情”按钮和地面／投影平滑切换。

## v7 性能与 WebGL 启动失败处理

- 地面淡出到零贡献后暂停 1024×1024 实时阴影贴图更新；保留地面本身与玻璃透射背景。返回首屏在有地面贡献的首帧恢复更新。
- 跳过完全透明的接触阴影，以及原 shader 已全部丢弃的长阴影。
- 长阴影保留 32 次采样与原来的柔化参数；增加保守边界排除和覆盖率为 1 时的提前结束。
- 复用内腔材质数组、相机方向向量，循环外计算间距与阴影强度。
- WebGL 创建失败时展示三个作品的普通封面入口与恢复提示，仍可进入完整详情。正常 WebGL 场景布局不变。

验证：1440×900、390×844 两种视口，共 14 组首屏、第二屏、过渡和倾转截图与 v6 像素一致；包含阴影 pass 的完整帧绘制调用由 41 降为 35，拖动采样位置由 33 降为 26。返回首屏阴影绘制立即恢复。以上是测试场景的调用统计，不代表帧率提升百分比。六卡切换、拖拽、详情及返回、减少动态效果、file:// 打开和模拟 WebGL 不可用后的详情入口通过。

若 Edge 报 `GL_VENDOR = Disabled`，并在 `edge://gpu` 提示 GPU 进程反复崩溃，则网页无法自行恢复浏览器 GPU。确认“使用图形加速（如果可用）”已开启，保存工作并正常重启 Edge；仍失败时检查浏览器与显卡驱动。此次网页更新没有修改浏览器安全选项、实验标志、驱动或系统策略。

## 2026-11-05 通用入口与渲染性能

移除首页底部硬编码的三个作品直达标签及对应样式、事件。键盘跳转改为通用作品浏览入口；WebGL 不可用时仍从作品数据生成普通封面入口。

主画布采样范围调整为 1.25–2 倍，总量上限 240 万像素。玻璃折射背景使用半宽、半高的独立缓冲；封面、页面文字、卡片尺寸、材质配色、几何细节、光照和阴影参数保持原设置。高密度屏上的细小边缘及玻璃折射背景会略柔和。Three.js 的窄范围本地补丁说明位于 `vendor/PATCHES.md`。

复用卡片点击区域的四个投影向量，避免每帧重复创建；投影边界不变时不重复写 CSS，拖动事件合并到渲染帧后更新点击区域。沿用现有的静止停绘、后台暂停和首屏停留不重绘机制。

验证：1440×900/DPR 1 与 390×844/DPR 3 的首页、第二屏、六卡切换、详情地址、占位保护、键盘跳转、静止停绘通过。自动轮播、暂停、切屏、拖动回弹、生命周期恢复和无 WebGL 时的备用封面入口通过，正常场景没有脚本错误。对应 Windows 文件经 SHA-256 核对后交付。

本地 Apple M1 / Chromium / ANGLE OpenGL 测量：1440×900 视口，用 GPU 时间查询对静态姿态重复渲染，每场景丢弃前 10 帧，统计后 30 帧。首屏中位耗时 6.78 → 5.65 ms，浏览屏 6.18 → 3.97 ms，分别减少约 17% 与 36%。这是本地 GPU 绘制耗时，不是目标 Windows 设备帧率结论。
